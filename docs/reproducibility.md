# Reproducibility

`scripts/build_validation_evidence.py` is a maintainer-only release command. It requires a
Git checkout and derives the release allow-list exclusively from tracked files. It is not part
of the ordinary source-ZIP reproduction route, and it never silently scans arbitrary files in
the working directory.

## Reference environment

The reference run used Windows 11 and Python 3.13.14 with pandas 3.0.3, NumPy 2.5.1, scikit-learn 1.9.0 and SciPy 1.18.0. Python 3.11 validation uses the explicitly pinned compatible NumPy 2.4.6 and SciPy 1.17.1 wheels; Python 3.12 and 3.13 retain the reference pins. Figures used Matplotlib 3.11.1 and Pillow 12.3.0. Notebook execution used NBClient 0.11.0. QGIS outputs were validated with QGIS 3.44.12 LTR.

## Determinism

The ordinary analytical-regression command uses `--check` by default. It recomputes the inbound
and outcome comparisons under `work/analytical-regression-check/`, compares schemas, values and
canonical assignment checksums with the locked public authorities, and proves that tracked files
do not change. Ordinary notebook validation also uses `--check`, which executes disposable copies
and preserves tracked notebook hashes.

Maintainers use `python scripts/build_analytical_regression_evidence.py --write-canonical` and
`python scripts/execute_public_notebooks.py --write-canonical` only in the exact Python 3.13.14
dependency contract recorded in the reference configuration. These explicit publication commands
regenerate canonical evidence; ordinary verification never falls back to writing tracked outputs.

- One JSON configuration controls paths, feature order, transformations, scaling and model settings.
- The national and telephone models use seed 2026, `k-means++`, 100 initialisations, 500 maximum iterations and the Lloyd algorithm.
- Practice codes remain attached for traceability and never enter a numerical feature matrix.
- Input matrices are pinned to PCADI commit `1239c63356acfb824277ee6fbaee25fa8df51313` and validated before use.
- The outcome-complete reference route requires strictly positive shares and adds no pseudocount.
- Closed historical resampling evidence is displayed only after its authority file passes checksum and schema checks.

## Release provenance

`outputs/validation/release_provenance.json` is generated by
`scripts/build_release_provenance.py`. The tracked record defines the stable pre-archive contract.
The exact source commit, archive SHA-256 and public-manifest SHA-256 are finalised in an external
sidecar after `git archive` completes. An archive cannot contain its own final hash without changing
that hash. This separates exact origin metadata from exact distribution checksums without a
self-referential claim.

`outputs/validation/notebook_ci_summary.csv` keeps canonical notebook regeneration separate from
the three local prepublication smoke runs. GitHub Actions run IDs and URLs remain empty until a
hosted workflow has actually run.
- The QGIS project uses a relative source path and a checksum-controlled GeoJSON layer.

## Validation levels

1. Complete input and cohort contracts.
2. Unit tests for configuration, transformations, composition geometry and edge cases.
3. National and telephone analytical regression tests.
4. Clean-kernel execution of all seven public notebooks without `allow_errors`.
5. Static links, paths, action pins, secrets and release-file allow-list checks.
6. QGIS structural and installed-runtime validation.
7. Clean package build, wheel install and CFF 1.2.0 validation.

Release archives are created from a clean Git checkout with `git archive`. Runtime caches, `work/`, local databases and private audit files are excluded.
